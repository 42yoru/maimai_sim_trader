## 先看效果

装好之后，群里收到的播报大概长这样（真实输出，语气来自你自己的 bot 人设）：

> 今天大盘绿绿的，麦麦就托着腮看戏啦～账户总资产 999,320.61，净值 0.9990，累计小亏 679.39，基本原地踏步。神华浮亏 1,184.35 最气人，招行也小亏 686.66，还好美的、伊利、长江电力都红着顶一顶。仓位 51.94%，现金 48%，手上有粮心里不慌。立讯逆势涨 3% 才不去追，等回踩再说，今天不折腾～

它每轮自己决定看多久盘一次（10~240 分钟），收盘后再补一份当日复盘。

## 三个必须认识的名字

如果你从没接触过东方财富，先花一分钟搞清楚这三样，后面的安装步骤就都是常识了。

### 东方财富妙想（插件的数据和账户来源）

「妙想」是东方财富做的金融数据服务，通过一个叫 **妙想 Skills** 的页面提供接口。
插件靠它拿到你的模拟账户余额、持仓、当日委托，以及**下单**的能力。
你需要做的：注册东方财富账号，在技能页领一个 **API Key**（一串 `mkt_v_` 开头的字符），它就相当于插件打开你账户的钥匙。

### 模拟组合（真正的「账户」）

**模拟组合**就是东方财富 App 里的模拟炒股账户——你可以在 App 底部「交易 → 模拟」里领到一笔**虚拟资金**（常见是 20 万，具体以 App 里显示为准），拿它买卖真实股票的真实价格，但钱是假的。
插件所有的买卖都发生在这个账户里。

> ⚠️ 领完模拟盘还差一步：必须回到妙想技能页，把 **API Key 和这个模拟组合绑定**。不绑定的话，插件的每次请求都会收到 `404 请先绑定账户~`。这一步是整个安装流程里最容易漏的。

### 腾讯行情（插件自己用的报价源）

判断买卖要看实时价格，插件用腾讯的免费快照接口批量拉取，**不消耗妙想的额度**。
这一项你完全不用管，知道有这么回事就行。

## 五分钟上手

### 第 1 步：注册并领一个模拟组合

手机上装东方财富 App，登录后按这个顺序：

1. 底部 **交易** → 上方 **模拟** → 领取模拟资金（目前 20 万）
2. 记下这个组合的名字，下一步要用

### 第 2 步：领 API Key

1. 在东方财富 App 首页搜「**妙想 Skills**」，或者直接打开 [妙想技能页](https://dl.dfcfs.com/m/itc4)
2. 页面上方可以领一个 API Key，复制保存

> Key 相当于你的账户密码，别发群里、别提交进 Git。插件也从不打印它。

### 第 3 步：把 Key 绑到模拟组合（最容易漏）

还在这同一个页面，往下滑找到 **「妙想模拟组合管理」** 这张卡片，里面有一个「绑定组合名称」的输入框：

1. 填上第 1 步里那个组合的名字
2. 点「去绑定」
3. 显示绑定成功就对了

**为什么非要绑这一步？** 妙想允许一个账号有多把 Key、多个组合，绑定就是告诉它「这串 Key 指的是哪个账户」。没绑的话接口一律返回 `404 请先绑定账户~`，插件看起来就像坏了。

### 第 4 步：装插件

```bash
cd MaiBot/plugins
git clone https://github.com/42yoru/maimai_sim_trader.git
```

`config.toml` 不用手动创建——仓库里只有 `config.toml.example`（因为真配置里会有 Key），
直接启动 MaiBot，宿主会按插件声明的配置模型自动生成一份完整的 `config.toml`。

想要带注释的版本，可以自己复制一份：

```bash
cp maimai_sim_trader/config.toml.example maimai_sim_trader/config.toml
```

### 第 5 步：填三处配置

打开 `plugins/maimai_sim_trader/config.toml`（或在 MaiBot 的 WebUI 插件配置页里改）：

```toml
[mx]
api_key = "mkt_v_你领到的Key"      # 第 2 步拿到的

[notify]
group_ids = ["你的群号"]            # 要播报到哪个群；留空就不播报

[owner]
owners = ["qq:你的QQ号"]            # 能改股票池、调节奏的人
```

**不填会怎样？** 插件照常加载，但会在日志里一条条提示你缺什么，不会静默失败：

- `未配置妙想 API Key…后台循环不会启动` → 填 `[mx] api_key`（也可以改用环境变量 `MX_APIKEY`），保存后循环自动开始
- `没有配置播报目标…` → 填 `[notify] group_ids`
- `owner.owners 为空…` → 人填 `[owner] owners`，否则改池子、调节奏的命令没人能用

> 仓库里的默认值全是空的，不会预置任何群号或用户 ID——别人装上不会往作者那边发消息。

### 第 6 步：验证

重启 MaiBot，然后在插件目录下跑一次自检：

```bash
python scripts/preflight.py
```

它一次确认四件事：Key 还有效、模拟组合能读、池子里每只票都拿得到价、播报群在 MaiBot 里唯一。
任何一项失败会返回非零退出码并说明原因，全程不打印密钥。

看到「全部就绪」，就等开盘了；也可以随时在群里发 `/股 试跑` 先看它打算怎么做（不下单）。

## 配置

配置有两种改法：直接编辑 `config.toml`，或者在 MaiBot 的 WebUI 插件配置页里点。

**WebUI 里的配置页是给中文用户重排过的**：四个页签「常用设置 / 交易 / 模型 / 高级」，
每个字段都有中文标签、一句「填什么、为什么」的说明，密钥用密码框显示，配置版本那两项只读。
第一次装想看要填什么，直接去「常用设置」那页就行。

`config.toml` 里常用的几节：

| 节 | 关键项 | 说明 |
|---|---|---|
| `[mx]` | `api_key` / `base_url` | 妙想 API Key（`mkt_v_` 开头），**别提交到仓库**；留空读环境变量 `MX_APIKEY`。`base_url` 必须是 `https://`，不建议指向本机/内网地址 |
| `[account]` | `slippage` / `max_position_ratio` / `min_cash_reserve_ratio` / `max_trades_per_day` | 让价、单票上限、现金底线、当日笔数上限 |
| `[risk]` | `profile` | 决策大胆程度：`steady` 稳健 / `aggressive` 激进 / `yolo` 梭哈，见下 |
| `[schedule]` | `sessions` / `min_interval_minutes` / `max_interval_minutes` / `manual_cooldown_seconds` | 交易时段、她自选间隔的合法范围、手动看盘的冷却 |
| `[model]` | `decision_task_name` / `report_task_name` / `max_tokens` | 默认决策用 `planner`、播报用 `replyer`；`max_tokens` 默认 4000，思考型模型给小了会只有思考没有正文 |
| `[notify]` | `group_ids` / `private_user_ids` / `private_enabled` | 默认全空：不填就不播报；私聊功能已实现但默认关 |
| `[owner]` | `owners` | 能改股票池、调节奏的人，格式 `qq:123456789`；留空时只有查询类命令可用 |

**人设不在插件里配。** 启动时从宿主读 `bot.nickname`（自称）和 `personality.personality`（人格），决策和播报都用你自己 bot 的那一套——插件本身不带任何角色设定。宿主没配人设时退回通用称呼「麦麦」并在日志里警告。

### 三档胆量：稳健 / 激进 / 梭哈

`[risk] profile` 控制它有多敢下手。档位**不是另起一套数字**，而是在 `[account]` 里你自己填的数上按倍数缩放：

| 档位 | 单票上限 | 现金底线 | 每日笔数 | 让价 | 气质 |
|---|---|---|---|---|---|
| `steady` 稳健（默认） | ×1.0 → 20% | ×1.0 → 20% | ×1.0 → 6 | +0 | 许可窄，理由讲不清就空着 |
| `aggressive` 激进 | ×1.4 → 28% | ×0.5 → 10% | ×1.8 → 11 | +0.1% | 额度放宽，但要说得出「为什么是现在」 |
| `yolo` 梭哈 | ×1.8 → 36% | ×0.1 → 2% | ×2.0 → 12 | +0.2% | 允许重仓和看错，亏了也是模拟盘 |

「→」后面是按默认 `[account]` 算出来的实际值。代码里还有一道**绝对上限**：单票不超过 40%、每日不超过 12 笔，档位再怎么调也翻不过去——一把梭到账户当天归零，就没什么好看的了。

档位会三处一起生效：倍数改代码里的校验、**实际生效的数字**写进规则、当轮气质写进 system prompt。光给形容词不够——模型很难从「宁可错过」推出该下多少，所以决策 prompt 里还有一块【这一轮的额度】：

```
【这一轮的额度】
- 单票上限 36%；现在最重的一只 贵州茅台(600519) 占 32.4%
- 总仓位上限 98%（现金至少留 2%），现在 41.3%，还能再加 56.7%
- 今天已下 3 笔，上限 12 笔，还能下 9 笔
```

额度算好了给它，它只需要决定用不用，不用自己估。

> 提醒一句：**更激进 ≠ 更赚钱**，只是换手更勤、仓位更重、波动更大。想看自家 bot 亏得更有观赏性，梭哈档确实更有效 (｡•̀ᴗ-)✧

## 命令

**查询类（所有人可用）**

| 命令 | 作用 |
|---|---|
| `/股 状态` | 总资产、可用资金、持仓、盈亏 |
| `/股 池` | 股票池清单 |
| `/股 委托` | 当日委托与状态 |
| `/股 记录` | 今天看了几轮，以及最近几轮的心情、判断和动作 |
| `/股 试跑` | 跑一轮决策但**不下单**，只回报打算做什么 |
| `/股 600036` | 查单只票实时价 |

行情查询是宽松识别的，下面四种写法等价，顺序随便：

```
/股 行情 600036
/股 招商银行
/股 600036 招商银行
/股 招商银行 600036
```

只写名字时会在股票池里找；池子里没有就请写六位代码。

**改动类（只有 `[owner] owners` 里的人能用）**

| 命令 | 作用 |
|---|---|
| `/股 加 600519 贵州茅台` | 加一只进池子 |
| `/股 减 600519` | 踢一只出池子 |
| `/股 节奏 15` | 15 分钟后再看一次盘；`/股 节奏 0` 表示立刻看 |

## 工具

聊天里她可以直接调这两个工具，不用敲命令：

| 工具 | 说明 |
|---|---|
| `sim_trader_query` | `action` 取 `status` / `pool` / `orders` / `history` / `quote`，分别是账户、池子、委托、最近判断、单只票行情 |
| `sim_trader_review` | 让她**此刻重新看一次盘并自行决定买不买**，跑完把心情、判断和动作回报给她。交易时段内**会真实下单到模拟盘**，闭市时自动降级为只看不做 |

所以群里有人喊「梭哈茅台」，她可以自己决定要不要调 `sim_trader_review`——听不听、动不动，都是它自己的判断，插件只提供能力。工具触发的这一轮**不会额外播报**，结果回到聊天里由它自己讲。

**这两个工具都没有权限门槛**：`sim_trader_query` 只是读数据，`sim_trader_review` 会让它跑一整轮决策。交易时段内可能真的下模拟单，闭市时只算不做；同一聊天流两次手动看盘之间有冷却（`[schedule] manual_cooldown_seconds`，默认 60 秒，**设成 0 等于关掉**，那时群里谁都能反复触发、烧你自己模型的额度），避免被刷屏。

> ⚠️ **换成真实账户之前，先给 `sim_trader_query` 加闸。** 现在 `status` / `orders` 不设门槛是合理的——账户是模拟盘、钱是假的。如果哪天把 `[mx]` 指向真实账户，请先把这两个 action 收进 `[owner] owners` 白名单，否则群里任何一句闲聊都可能让模型把账户和当日委托念出来。

真下单仍然受 `max_trades_per_day`、单票上限、现金底线约束。

## 她怎么工作

```
每轮（她决定下次隔多久）：
  妙想 balance / positions / orders  →  腾讯快照拉池子行情
      →  模型给出 JSON 决策（动作 / 池子增删 / 下次间隔 / 想说的话）
      →  代码按限价单规则下单
      →  有动作或她开口，就发到群里
收盘后：补一份当日复盘（每天一次）
```

每轮结束后会留下一条结构化记录：**时间、心情、判断理由、实际执行或被拦下的动作**。下一轮决策时，prompt 里会带上最近 8 条的这些记录，所以她能接着上一轮的思路往下想——

> 上一轮「600519 回到 1680 再考虑接一手」→ 这一轮「真跌到 1678 了，那手可以补了」

而不是每轮都对着盘面从零开始。状态文件里最多留 24 轮，跨日不清空，`/股 记录` 能看到最近 6 轮的完整判断。

妙想只收**限价单**，所以「想买」会换算成 `最新价 × (1 + slippage)`，「想卖」换成 `最新价 × (1 - slippage)`，保证挂在能成交的一侧。

每轮至少 3 次妙想调用（余额、持仓、委托），有买入卖出时再多一次；腾讯行情不占额度。这也是为什么她默认 30 分钟看一眼，而不是每分钟。

## 常见问题

**打开 App 找不到「妙想 Skills」**
在东方财富 App 首页的搜索框里搜这四个字，或者直接开 [技能页链接](https://dl.dfcfs.com/m/itc4)。网页版也能进去，但领模拟资金那一步通常得在 App 里做。

**`404 请先绑定账户~`**
这是新手最常撞的坑：Key 领了，但没跟模拟组合绑定。回到[妙想技能页](https://dl.dfcfs.com/m/itc4)，在「妙想模拟组合管理」卡片里填上组合名点「去绑定」。绑完再跑 `python scripts/preflight.py` 验证。

**接口报额度用完 / 调用被拒**
妙想的 Key 有调用额度（目前是限时免费体验，规则以官方页面为准）。插件每轮固定 3 次调用（余额、持仓、委托），按默认 30 分钟一轮、一天两个交易时段算，大约 8 轮、24 次；嫌费额度就把 `[schedule] default_interval_minutes` 和 `max_interval_minutes` 调大，它可以 240 分钟才看一次，一天就只剩 1 轮。

**试跑报「模型只输出了思考过程没有正文」**
决策模型的 `max_tokens` 太小，思考阶段就把额度用光了。把 `[model] max_tokens` 调大（默认 4000）。

**群里收不到播报**
依次检查：`[notify] group_enabled` 是否为 true、`group_ids` 里的群号是否正确、`account_id` 留空是否匹配到了多个账号。日志里会有 `找不到群 xxx 的聊天流` 或 `命中 N 条聊天流` 的提示。

**她好几天都不交易**
这是设计允许的——规则里写明「没机会就不动」。用 `/股 记录` 看她最近几轮的判断，`/股 节奏 15` 可以让她更勤快地看盘。

**播报语气不像我的 bot**
插件从宿主读 `bot.nickname` 和 `personality.personality`。如果宿主没配人设，会退回通用称呼并在日志里警告。

## 把账户清零重新开始

插件**不持有资金，也改不了净值**——钱和持仓都在东方财富妙想的模拟组合里，所以重置要分两步。

**第 1 步：妙想那边**

| 想要的效果 | 怎么做 |
|---|---|
| 彻底重来（净值回到 1.0000） | 在[妙想技能页](https://dl.dfcfs.com/m/itc4)新建一个模拟组合、重新绑定，再把 `[mx] api_key` 换成新 Key |
| 只是清空持仓 | 在妙想 App 的模拟组合页面把持仓卖掉、挂单撤掉。注意这样只是回到空仓，**累计盈亏和净值还是旧的** |

**第 2 步：插件这边**

先停掉插件（WebUI 里关掉，或直接停 bot），再删文件，否则运行中的循环可能把它写回去。

数据目录在 MaiBot 根目录下：`data/plugins/github.42yoru.maimai-sim-trader/`

| 文件 | 删掉以后 |
|---|---|
| `state.json` | 当日轮数/笔数、空仓起点、最近几轮判断全清零，下一轮从「这是第一轮」开始；当天已经发过收盘复盘的记录也会丢，重启后可能再补一条 |
| `watchlist.json` | 股票池回到默认清单。**不想丢池子就别删这个** |

不删 `state.json` 也能跑，但「最近几轮」里还挂着旧账户的判断，她容易拿旧仓位的思路往新账户上套——换了组合的话建议一起清。

## 已知边界

- 妙想**不支持市价单**；深市 ETF（`159` 开头）不支持。
- 数量必须 100 的整数倍，A 股 T+1，当日买的不能当日卖。
- 模拟组合须在妙想技能页绑定后 `mockTrading/*` 才可用，否则返回 `404 请先绑定账户~`。
- 插件只用了妙想的**账户与下单**接口；妙想还有资讯搜索、自然语言数据查询、智能选股等技能，插件目前没有接。
- 决策模型每轮一次调用；她可以把间隔拉到 240 分钟来省额度。
- 插件不接任何真实券商通道，纯模拟盘。
- **两个 HTTP 客户端都关掉了 `trust_env`**（`mx_client.py` / `quotes.py`），即**不走系统代理和 `HTTP(S)_PROXY` 环境变量**。这是为了躲开畸形代理变量导致 httpx 建 URL 崩溃的老问题。部署环境如果必须通过代理才能出网，妙想和腾讯行情都会连不通，需要给主机配透明代理，或把 `[mx] base_url` 指到可直连的地址。

## 文件结构

```
maimai_sim_trader/
├── plugin.py           # 插件入口：配置模型、后台循环、命令、工具
├── mx_client.py        # 妙想 HTTP 客户端（账户 / 委托 / 下单）
├── quotes.py           # 腾讯行情快照，批量拉价并解析
├── positions.py        # 持仓字段适配（字段名有变体，认不出代码就报错）
├── trading.py          # 限价换算、整手、仓位与现金约束
├── decision.py         # 决策 prompt 与严格 JSON 校验
├── report.py           # 播报文案（语气归模型，数字归代码）
├── watchlist.py        # 股票池，原子写
├── state.py            # 运行状态：节奏、计数、每轮的判断与动作记录
├── query_args.py       # 命令参数的宽松识别
├── fmt.py              # 金额 / 百分比 / 盈亏格式化
├── scripts/preflight.py# 开盘前自检（仅开发者本地用，不是运行时依赖）
├── tests/              # 单测，不碰网络
├── config.toml.example
└── _manifest.json
```

`scripts/` 下的东西只给开发者在本地排查用：`preflight.py` 会以只读方式打开宿主实例的
`data/MaiBot.db` 查 `chat_sessions`，宿主库结构一变它就会失败——**插件运行时从不碰宿主数据库**，
一律走 `chat.get_group_streams` 能力。别把 `scripts/` 当运行时依赖，也别在部署脚本里调它。

## 测试

```bash
cd plugins/maimai_sim_trader
python -m unittest discover -s tests -t .
```

单测不碰网络，只验限价换算、整手、资金/仓位约束、决策解析、池子增删、持仓字段适配、命令参数识别、主人校验和整轮流程编排。
